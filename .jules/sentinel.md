## 2024-04-07 - URL Parameter and Header Injection Risks in Userscripts
**Vulnerability:** Untrusted input (`targetVal`) injected directly into URL query parameters (`gemini-2.5-flash:generateContent?key=${targetVal}`) and HTTP Authorization Headers (`Bearer ${gameState.apiKeys.k}`). Error objects from JSON parsing were directly logged to the console.
**Learning:** Userscripts interfacing with external APIs and parsing DOM-based data must validate, sanitize, and encode data precisely as server-side code would. Unsanitized input into query strings can lead to SSRF or parameter pollution, and newlines in tokens can lead to HTTP Header Injection. Furthermore, directly printing unvalidated JSON payloads to `console.error` can lead to log injection or log-based XSS depending on the browser console implementation.
**Prevention:** Always use `encodeURIComponent()` for variables inserted into URL structures. Call `.trim()` and reject newlines for any value used in an HTTP header. Strip raw input objects before logging to the console (e.g. log static strings). Add explicit `parseFloat()` bounds to numerical logic that originates from unstructured or untrusted input (LLM JSON).

## 2024-05-24 - API Key Exposure in Userscript DOM
**Vulnerability:** API keys were being populated directly into `document.getElementById('...').value` during userscript initialization.
**Learning:** Setting sensitive information directly into the value attributes of DOM elements in userscripts exposes those credentials to any malicious scripts or extensions running on the host page via `.value` extraction.
**Prevention:** Implement a "Placeholder Security Pattern". If a key exists in secure storage, keep the input value empty but set the `placeholder` to `'•••••••• (Saved)'`. During save actions, only read the `.value` if it is not empty, otherwise fallback to the memory state, and properly support explicit deletion if the placeholder differs. Consumer functions should fallback to securely stored keys if the DOM value is empty.
**Action:** When implementing the placeholder security pattern for API keys in userscripts, ensure functions consuming these keys check the DOM input `.value` first and fall back to securely stored state. When saving keys, support explicit deletion by distinguishing between an untouched field and a user intentionally clearing the key (e.g., verifying if the `.value` is empty and the placeholder does not indicate an existing saved key, or if the `.value` contains only whitespace while not being an empty string).
