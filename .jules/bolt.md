## 2024-05-18 - [Preventing Layout Thrashing in MutationObservers]
**Learning:** Found a performance bottleneck in `cinematic-rp-extension-beta0.2.user.js` where a `MutationObserver` used `node.textContent || node.innerText || ""`. Accessing `innerText` forces a synchronous layout recalculation (reflow), which is extremely expensive when executed repeatedly on every added node. Furthermore, a heavy regex was being run on every text node.
**Action:** Removed the `innerText` fallback and introduced an early return fast-path (`if (!text.includes('"loc"')) return;`) to bypass the regex when the target keyword is absent. Always prefer `textContent` in observers to avoid layout thrashing, and use cheap string checks before expensive regex operations.
## 2026-07-08 - [Cache Primitive Values to Prevent Redundant DOM Mutations]
**Learning:** Found a performance bottleneck in `cinematic-rp-extension-beta0.2.user.js` where the `renderState` function rebuilt the UI blocks and reassigned `textContent` on every state update, even if the actual data points (like tokens, loc, or specific stats) hadn't changed. Given that state parsing happens frequently (on every DOM mutation with the target keyword), these redundant DOM updates can compound and cause unnecessary layout recalculations (thrashing).
**Action:** Introduced a `lastRenderState` object alongside `domCache` to hold primitive copies of the last rendered state values. Implemented fast-path early returns within `renderState` (e.g., `if (lastRenderState.stats[key] === stat.val) return;`) to safely skip DOM assignments when the underlying value hasn't mutated. Always cache and diff primitive state objects before interacting with the DOM to skip redundant mutations.
