## 2024-05-18 - [Preventing Layout Thrashing in MutationObservers]
**Learning:** Found a performance bottleneck in `cinematic-rp-extension-beta0.2.user.js` where a `MutationObserver` used `node.textContent || node.innerText || ""`. Accessing `innerText` forces a synchronous layout recalculation (reflow), which is extremely expensive when executed repeatedly on every added node. Furthermore, a heavy regex was being run on every text node.
**Action:** Removed the `innerText` fallback and introduced an early return fast-path (`if (!text.includes('"loc"')) return;`) to bypass the regex when the target keyword is absent. Always prefer `textContent` in observers to avoid layout thrashing, and use cheap string checks before expensive regex operations.
## 2024-05-19 - [Fast String Boundaries for JSON Parsing]
**Learning:** Found a performance bottleneck where a greedy regex `/\{[\s\S]*"loc"[\s\S]*\}/g` was used to isolate JSON blobs containing the `"loc"` key in the DOM text parser. This approach caused catastrophic backtracking or O(N^2) complexity on very large text blocks, significantly impacting layout rendering times when scaling up RP content length.
**Action:** Replaced the heavy greedy regex with fast O(N) string index lookups `indexOf('{')` and `lastIndexOf('}')` to safely extract bounds, verifying that the extracted block `.includes('"loc"')` to ensure target keyword adjacency. Always prefer string index operations over unbounded wildcard regex operations in performance-critical synchronous parsing paths.
