## 2024-05-18 - [Preventing Layout Thrashing in MutationObservers]
**Learning:** Found a performance bottleneck in `cinematic-rp-extension-beta0.2.user.js` where a `MutationObserver` used `node.textContent || node.innerText || ""`. Accessing `innerText` forces a synchronous layout recalculation (reflow), which is extremely expensive when executed repeatedly on every added node. Furthermore, a heavy regex was being run on every text node.
**Action:** Removed the `innerText` fallback and introduced an early return fast-path (`if (!text.includes('"loc"')) return;`) to bypass the regex when the target keyword is absent. Always prefer `textContent` in observers to avoid layout thrashing, and use cheap string checks before expensive regex operations.
## 2024-05-18 - [Preventing Layout Thrashing via Primitive State Caching in renderState]
**Learning:** Found a performance bottleneck in `cinematic-rp-extension-beta0.2.user.js` where `renderState` blindly updated the DOM (text content and class names) for every state piece during high-frequency UI updates. These redundant DOM iterations and modifications force unnecessary layout reflows, causing layout thrashing even when the underlying data hasn't changed.
**Action:** Introduced an in-memory `lastRenderState` object. Before updating the DOM in `renderState`, compare the current `gameState` primitives (`loc`, `tokens`, and individual stat `val`) against `lastRenderState`. Early return per state piece safely bypasses redundant DOM manipulations and expensive loop iterations, preventing layout reflows.
